# Memo template — boote's one-page memo

A one-page memo (YC style: short, blunt, numbers-driven) for presenting an idea. Fill in the placeholders. If it's written on the founder's behalf, honor the host voice (the `voice` slot). No emoji. **Redaction per the host's `output_style`:** nothing confidential.

> Length guide: the whole memo should fit on one A4 page (~2 minutes to read). Compress ruthlessly.

---

```markdown
# <idea name> — <tagline>

**Version:** v<X.Y>  |  **Strategic fit:** <...>  |  **Audience:** <board / experienced / team>  |  **Date:** <YYYY-MM-DD>

## Problem
<Who, what pain, how acute. One short paragraph. If you have evidence or a quote, one line.>

## Insight (why we see this)
<The insight others don't see, or don't take seriously. The unfair advantage.>

## Why now
<What has recently changed that makes this feasible/attractive now.>

## Solution
<The simplest version that proves the value. Not a feature list.>

## Evidence so far
<Everything we have: user interviews, a market number with a source, a demand signal. If it's thin, say so honestly — "still an assumption.">

## Market and model
<Market size (with source + date), how it makes money, where the first customers come from.>

## The biggest risk
<The riskiest assumption + the cheapest way to test it.>

## The ask
<Exactly what you want from the audience: approval for a pilot? A budget of $X? An intro? A go/no-go decision?>
```

---

Notes:
- Market numbers always come with a **source + date**; if a number is stale or a guess, label it explicitly.
- The "Evidence so far" section matters most — an experienced mentor looks there first. If it's empty, the idea is still raw.
- If a ROFR or a red line is relevant, mention it in one line under "The biggest risk."
